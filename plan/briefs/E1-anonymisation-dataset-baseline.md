# Brief E1a — anonymisation gate: dataset + regex baseline (first half of E1)

Read first: `slm/plan/briefs/_preface.md`, then `slm/plan/EXPERIMENT-PLAN.md` section "E1", and
`slm/research/landscape/anonymisation-synthetic-docling-finetuning.md` section 1. Your folder: `slm/experiments/e1/`.

1. **Dataset** (`build_dataset.py` → `data/*.jsonl`, each row `{id, lang, text, spans:[{start,end,type}]}`, `DATA.md` with
   source + licence + counts):
   - 400 French + 400 English rows from the OpenPII dataset named in the plan (CC-BY-4.0). Find its exact Hugging Face id
     in the research note; if the note does not give one, list candidates with
     `curl -s "https://huggingface.co/api/datasets?search=openpii&limit=20"` and read the licence field before using any.
     Map its entity labels to our types in `DATA.md`.
   - 100 synthetic French claim emails generated by `gen_fr_claims.py` (Faker, MIT, in your own venv): each with a NIR
     whose 2-digit key is correct, an IBAN FR76 with a valid mod-97 check, an SIV plate (AB-123-CD), a SIREN with a valid
     Luhn check, a date of birth, two named persons and a garage name. Spans are exact by construction. Label them synthetic.
2. **Regex baseline** (`regex_baseline.py`): EMAIL, PHONE (FR and international), NIR (with key check), IBAN (mod-97),
   CARD (Luhn), SIREN (Luhn), PLATE (SIV and older formats), DATE, POSTCODE+city, ADDRESS, and PERSON by rules (titles,
   greetings, sign-offs, relation words, a first-name list). Start from the detectors in
   `slm/app/second-look/index.html` (search `PATTERNS` and `nameCandidates`) and port them to Python faithfully, then
   improve; note every change.
3. **Evaluation** (`eval.py` → `results.json`): per-type recall at boundary match (overlap ≥ 50 % of the gold span) and
   precision; document-level leak rate of direct identifiers (a document leaks if any gold NIR / IBAN / PHONE / EMAIL /
   PLATE / PERSON is not covered); placeholder round trip (pseudonymise → restore → exact match rate). Separate FR and EN,
   OpenPII and synthetic.
4. **Pass bar** (from the plan): leak rate ≤ 1 % per language at precision ≥ 0.80; recall ≥ 0.98 on NIR / IBAN / PHONE /
   EMAIL / PLATE and ≥ 0.95 on PERSON; 100 % round trip. **Kill rule:** if the regex baseline alone meets the leak-rate
   bar, say so — that ends the model half of E1.
5. `REPORT.md`: numbers from `results.json` only, the worst misses (10 examples with the type missed), and what the second
   half (Presidio + French recognisers, GLiNER2-PII) should target.
