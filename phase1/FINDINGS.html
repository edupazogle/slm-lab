Research memo · 2026-09-20 · Valheim / BizLoop

Small models, real triage.

Hands-on findings from testing needle3 — a 121M-parameter on-device model for tool-calling and structured extraction — alongside AnythingLLM, docling, and three general-purpose chat SLMs, against a claims-triage use case.

By the supervisor session (deepseek-v4-pro) · all figures measured on a Ryzen 7 7800X3D + RTX 4070 (12 GB), WSL2 · full source in docs/slm-research/FINDINGS.md

The headline

needle3 is not a chatbot — it's a claims-triage primitive. It extracted a full claim record and a PII record (name, phone, email, address, policy, national ID) perfectly in ~0.5 s on CPU with zero GPU, and its grounding gate suppressed a hallucinated claim on sparse input. Its weaknesses are real too: relative-time resolution fails, and confidence can read 0.99 while wrong. Fine-tuning the pipeline works end-to-end, but my 179-example synthetic dataset was too small to help (0.72 → 0.72) — data, not tooling, is the bottleneck.

Three ideas matter more than parameter count: (1) intelligence laddering — pick the depth that fits the device and the task; (2) grammar-constrained decoding — output is compiled against your schema, so JSON can't be malformed and enums can't leave their set; (3) confidence + grounding — a calibrated "am I sure?" score plus a gate that withholds calls it can't justify from the input.

04needle3 experiments

All results real runs, CPU, ~105 MB peak RAM, ~0.5 s mean latency.

Structured extraction — excellent

A messy claim paragraph → typed record, all five fields correct: policy AXA-77812, claimant "Mr. Jean Dupont", date 2026-08-30, type "car collision", amount 2150.5.

PII extraction (anonymisation feed) — excellent

From a customer email, every PII field came back correctly: full_name, phone, email, address, policy_number, id_number (French national ID). That's the raw material for a local redaction/pseudonymisation step before text ever leaves the device.

Confidence tracks completeness — in simple cases

Five claims benchmarked: confidences [0.98, 0.55, 0.77, 0.94, 0.99]. The 0.55 was the one claim with no amount — the score dropped exactly where a human would pause. Mean latency 0.59 s, p50 0.50 s.

The grounding gate is the safety feature — and it works

Sparse input ("A customer wants to file a claim for a stolen bicycle") → the model tried to hallucinate a full claim (policy "AC-777", amount 50.0) but the engine suppressed the call and flagged 4 ungrounded fields. A client that does nothing gets a refusal, not a fabricated claim.

Weaknesses — measured, not guessed

  • Relative time fails. "call back the day after tomorrow at 3pm on 04 11 22 33 44" → the name landed in contact_number, the phone in when, and confidence read 0.99.
  • Disambiguation scrambles. Under multi-action pressure the claimant name became MRD-7843.
  • Partial claims fabricate. "Log a theft claim for 800 euros" → policy_number="800 euros", claimant="theft", at confidence 0.87.
  • Non-English degrades. Spanish ~1.7× tokens; "correct Spanish calls measured at 0.0" confidence. French carries the same risk.
  • Markdown tables break it. Feeding docling's table output made it hallucinate; flattening to key: value prose fixed it.

Classification is label-sensitive

An enum field is a classifier, but labels must match user vocabulary. Abstract labels like line_of_business: ["motor","home","liability"] misfired ("…before I travel" → travel; a store slip-and-fall → motor). Sentiment/urgency (labels with surface cues) worked far better.

The full agentic loop works — and smaller rungs suffice

run() chained a two-step request ("log … then flag …") into two sequential calls correctly. And needle2 (45M) produced byte-identical output to needle3 (121M) on clean extraction — the ladder means you run the smallest rung that fits.

05The triage contract

needle3's confidence score maps onto a routing queue. This is the pattern the whole thing is built around:

Act — ≥ 0.7

Confident call → auto-execute (log the claim, schedule the callback).

Confirm — middle band

Show the extracted call + its reasoning to a human (or route to a bigger model) for one-tap approval.

Refuse — empty

Off-topic / no tool covers it → empty call. Treat as "I can't do that here."

gemma-4-e2b-hybrid does the same "escalate when unsure" inside a 5B multimodal model via a probe head — matching Gemini 3.1 Flash-Lite while running only 15–35% of queries through the big model.

06docling, and the doc → fields pipeline

  • HTML → Markdown: correct, 0.6 s, table reconstructed.
  • PDF → Markdown (a motor-claim form): correct table + description, OCR on GPU (RapidOCR). 45 s incl. first-run model downloads.
docling turns a PDF into clean Markdown; a flatten step (table → key: value prose); needle3 turns that into a typed claim + PII record. Document in → fields out, both locally.

08Fine-tuning (LoRA on GPU)

Since needle generate-data needs an unavailable OpenRouter key, I wrote a synthetic-data generator (template + entity substitution, answers derived deterministically) → 179 grounded EN+FR examples → LoRA (rank 16), 20 epochs on the 4070, 22m35s, val loss 0.294 → 0.032, exported a 63.5 MB tuned.cact.

The lesson: the pipeline is a real asset — train a 121M model to a custom toolset in ~20 min, export a 63 MB artifact that runs on the same CPU engine. The hard part is the dataset: argument grounding (exactly what claims needs) takes thousands of varied, reasoning-labelled examples with ~1/8 off-topic. My generator is the right start; it needs real (anonymised) claims phrasing and 5–10× more volume.

09The four patterns people deploy

Pattern 1Distil big → tiny specialist. needle v1 = Gemini 3.1 distilled into 26M params. Take frontier behaviour on one task, distil it down, ship at a fraction of the cost.
Pattern 2Confidence-gated escalation. Run the cheap model; below a threshold, route to a bigger model or a human. The single most relevant pattern for claims.
Pattern 3On-device extraction as the anonymisation gate. Extract PII/fields locally so raw text never leaves the boundary. Privacy by construction.
Pattern 4Fine-tune-to-schema. "The schema is the product." A 4-layer subnetwork tuned on one product's tools matches a frontier model on that task.

10For AXA / BizLoop — and the asks

  • Anonymisation: needle3's PII extraction is the enabling step — pull structured PII on-device, redact/pseudonymise the matched spans before sharing with a cloud LLM or partner platform. (Microsoft Presidio does the same job; needle3 does it locally, ~0.5 s, no network.)
  • Synthetic data: chat SLMs generate plausible synthetic claims; needle3 structures/validates them so downstream systems can be tested without touching real policyholder data. (I used template+entity generation to build the fine-tune set.)
  • Document understanding: docling → flatten → needle3 is the "document in, fields out" primitive for claims letters and policy PDFs.
  • Claims triage: the strongest fit — read a request, decide what it wants, fill fields, decide confidence, route act/confirm/refuse.
  • Copilot / MCPs: needle3 already accepts OpenAI function-calling wrappers, so it can act as a fast, local, grammar-constrained tool-router in front of an MCP host; hybrid small→large keeps frontier-model calls (and cost) on the hard minority only.

AXA-specific applications above are domain reasoning (web search was blocked in this environment); everything else is measured.

11Recommendations

  1. Approve Ollama for the chat models — GPU-automatic, AnythingLLM-native; removes the CPU slowness in §07. (The curl|sh installer was denied by the permission policy; one approval unblocks it.)
  2. Mobile access — run once in an admin PowerShell: netsh interface portproxy add v4tov4 listenaddress=192.168.1.36 listenport=3001 connectaddress=172.20.139.222 connectport=3001 + a firewall allow rule for TCP 3001.
  3. Fine-tune on real French claims to fix the French weakness — swap in anonymised phrasing, scale to ≥1k examples.
  4. Run docling→needle3 end-to-end on a real claims PDF and score it against human extraction.
  5. Build the triage queue around needle3's act/confirm/refuse bands with a human-in-the-loop review surface.
